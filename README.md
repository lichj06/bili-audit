# bili-audit

**B 站互动数据形态观察器** —— 用公开接口建立「正常互动分布」的基线，并测量两种相反的数据形态：

```
注水（假互动）  分布过于【规则/突变】：点赞率异常高而投币比异常低、评论高度模板化
问号（真共鸣）  分布有【结构】：短促、密集、情绪集中 —— 用「问号指数」量化
```

**两者是同一个问题的两面：这批互动数据是「真的吗」「是什么形状」。**

---

## 30 秒看懂

**这是什么**

把 B 站视频的互动数据拿来量一量，看它长成什么形状。

**要解决什么问题**

我们平时说一个视频「刷量了」，凭的往往是「这个比例看着不对劲」。可到底多少算不对劲？没人给过基线。所以我想先干一件更笨的事：把一批正常视频的互动比算出来，看看正常本身长什么样。做完才发现，麻烦比想象的大。

**我做了什么**

只调公开接口，不登录、不碰需要授权的东西，抓了热门榜的视频统计和评论，算出点赞率、投币比这些指标。关键是算「偏离群体分布多少」时用了有符号的稳健 z 分数（中位数 + MAD），而不是自己拍一个固定阈值。因为一比较就发现，正常视频之间的互动比本来就差着量级（旧版报告写的是「10–100 倍」；`verify.py` 会检查现版报告不再把这个数字当结论用），阈值卡死在这种方差上根本没有意义 —— 所以「用固定阈值判断刷量」在方法上就是错的。

**做出来了什么**

- 一套只用公开接口的采集工具，一次跑通采集 → 匿名化 → 分析 → 画图 → 自检五个环节
- 一份正常互动比的基线：点赞/播放、投币/点赞、收藏/点赞、评论/播放的中位数与极差（n = 18）
- 一个「问号指数」——评论里含 `?` / `？` 的比例，用来量化那种被内容震到的真共鸣（353 条唯一评论）
- 一个 29 项自检脚本 `verify.py`，跑一遍能把报告里每个数字重算出来，隐私泄漏也一起查

**为什么做这个**

我一开始的好奇很简单：那些看着就不对劲的数据，到底哪里不对劲。但做下去发现真正的判断力不在抓出谁，而在知道方法能说到哪一步 —— 正常视频之间的互动比能差 10–100 倍（旧版报告的说法，现版已不作为结论），那么「偏离」压根不等于「注水」，真实爆款、分区差异、官方推广都会造成同样的偏离，拿固定阈值去判，等于在制造冤案。所以我最后只描述形态、报偏离度，不判任何视频注水，也不接受单视频委托：一个视频没有分布，就没有基线。样本只有 45 个视频、18 个取到评论，这个坑我在 README 里写清楚了，没捂着。

> **本批样本量（先说清楚）**：热门榜取到 **45 个视频**，其中只有 **18 个**取到评论。
> 所有评论类指标（问号指数、重复率）的 n = **18**，不是 45。
> 去重后唯一评论 **353 条**（原始写入 1086 行，其中大部分是同一页被重复写入 —— 见下文）。
> 45 个视频的互动比在 `data/analysis.json` 里是逐条算的，但报告的区间/中位数一律标 n=18。

## ⚠️ 先说清楚这个项目是什么、不是什么

**它是什么：**
- 一套用**公开接口**（无需登录）采集 B 站视频统计与评论的工具
- 一个**正常互动比基线**（点赞/播放、投币/点赞、收藏/点赞、评论/播放 的中位数与极差）
- 一个「数值偏离群体分布程度」的计算器（**有符号**稳健 z 分数，中位数 + MAD）
- 一个「问号指数」——评论中含 `?`/`？` 的比例，用于量化"预期违背型共鸣"

**它不是什么：**
- ❌ **不是刷量工具**，也不提供任何获取虚假互动的方法
- ❌ **不接受单账号委托，不出具单视频报告** —— 任何人拿单个视频来问「它刷了吗」，本项目的回答都是「不知道」。
  单视频没有分布，就没有基线可依据；只算一个视频的 z 分数等于用噪声下结论
- ❌ **不判定任何视频「注水了」** —— 只报告指标偏离程度，不做指控
- ❌ 不是全站普查 —— 样本来自热门榜，是抽样

**为什么不做「判定」：**

偏离 ≠ 注水。真实爆款、分区差异、官方推广、活动运营都会造成同样的偏离。
一份把"指标异常"直接等同于"刷量"的报告，等于在制造冤案。

## 一个必须讲明的样本约束

```
样本来自【热门榜】= 平台推荐位
     ↓
刷量视频通常上不了热榜
     ↓
所以本批样本里【本来就抓不到注水】
```

**这不是缺陷，是设计**：本项目建立的是**正常分布基线**。
有了基线，任何视频都可以拿来比 —— **基线才是可复用的产出。**

## 隐私：发布版里有什么、没有什么

原始采集里含**真实 UP 的 mid/昵称（45 个，含公众人物）**、**评论文本**、
以及 `sha1(mid)[:12]` 这种**一次公开 API 就能反查回 mid** 的哈希。这些一律不发布：

| 文件 | 内容 | 进 git？ |
|---|---|---|
| `data/raw-local/videos.jsonl` | 原始：真标题 + 真 UP + stat | ❌ `.gitignore` |
| `data/raw-local/comments.jsonl` | 原始：1086 行评论原文 + uid_hash | ❌ |
| `data/raw-local/video_id_map.csv` | `v01…v45` ↔ 真标题/真 UP 的对照表 | ❌ |
| `data/videos.jsonl` | 发布版：stat + `owner_ref`（`u01…`），**无标题无 UP 名** | ✅ |
| `data/comments.jsonl` | 发布版：**每视频一行的派生指标**，无文本无 uid | ✅ |
| `data/analysis.json` | 逐视频指标，键是 `v01…` | ✅ |
| `report/*.md` | 全部用 `v01…` 标注，不出现真标题 | ✅ |

`analysis/anonymize.py` 负责这次拆分，跑完会**自检发布版里搜不到任何真标题/UP 名/评论文本/uid**。

## 数据来源（全部公开，无需登录）

| 接口 | 用途 | 实测状态 |
|---|---|---|
| `x/web-interface/view?bvid=` | 视频信息 + stat（播放/点赞/投币/收藏/分享/评论/弹幕） | ✅ 可用 |
| `x/web-interface/popular` | 热门榜（批量取视频） | ✅ 可用 |
| `x/v2/reply/main?type=1&oid=` | 评论（JSON，每页 20 条） | ⚠️ **只能拿第 1 页** |
| ~~弹幕~~ | ~~弹幕文本~~ | ❌ **不可用** —— 需登录 + 签名；旧 XML 端点只返回头部 |

### 已知接口缺陷（实测，2026-09-23）

```
① x/v2/reply     只返回 3 条   → 换 x/v2/reply/main 才给满 20 条
② pn 参数无效   实测 pn=1/2/3 返回同一批 rpid（314719551921 / 318314835872）
                 → 评论分页不可用，只能拿第 1 页（20 条/视频）
                 → 采集器现在只取 1 页，并在发现重复页时提前停止
③ 接口返回码被旧版丢掉 → 「60–80 次请求后限流」这句结论**没有日志支撑**
                 → 现在每次请求都写 data/raw-local/fetch_log.jsonl（含 code）
④ 弹幕需要登录 + 签名：新端点返回的是配置信息；旧 XML 端点解压后无 <d> 元素
```

## 两类指标怎么算

### A. 互动比

```
点赞率   = like / view
投币比   = coin / like      ← 关键：投币成本远高于点赞
收藏比   = favorite / like
分享率   = share / view
评论率   = reply / view
弹幕率   = danmaku / view
```

**逻辑**：刷播放和刷赞便宜，刷投币/收藏贵。
**若某个视频的点赞率显著高于群体、而投币比显著低于群体 → 值得核对**（不是定罪）。

### B. 评论文本特征（在**去重后**的文本上算）

```
完全重复率      1 − 去重后条数 / 总条数
前 8 字重复率   1 − 去重后前缀数 / 总条数   ← 水军模板的典型特征
平均等级        评论者账号等级均值
```

**去重规则（必须先做这一步）**：按 `(aid, 评论文本)` 精确去重 —— 同一视频内完全相同的文本只计一次。
不去重的话，「重复率」测的是采集器的分页 bug，不是评论区的形态（旧版就是这样，见下）。

### C. 问号指数

```
问号指数       含 ? 或 ？ 的评论占比
三重问号率     含 ??? 或 ？？？ 的评论占比   ← ⚠️ 本批数据里恒为 0，见「已知局限」
每千字问号数   总问号数 / 总字数 × 1000
```

**为什么用问号**：`？？？` 是**预期违背**的直接标记 —— 观众被内容震到、看不懂、或发现反转时才会打出来。
它同时触发**弹幕、评论、完播、二刷**，是四合一的高价值互动信号。

### 偏离度怎么算（**保留符号**）

```
稳健 z = (x − median) / (1.4826 × MAD)
阈值 |z| ≥ 3，方向性指标只看单侧：
  点赞率   取【高】尾（> +3）
  投币比   取【低】尾（< −3）   ← 投币刷不动，注水形态表现为投币比偏低
  前8字重复率 取【高】尾（> +3）
```

比普通标准差稳健 —— 少数极端值不会污染阈值。

> ⚠️ **旧版把 z 取了绝对值**，于是「投币比偏低」用 `z >= 3.0` 判定，方向反了、**永远不可能成立**。
> 本版 z 有符号。另外本批 n=18 的数据里「投币比偏低」的极端值只有 z = −1.45，**够不到阈值** ——
> 报告会明确写「本批不可达」，而不是含糊地写「0 个触发」。

## 用法

```bash
# ① 采集（默认限速 0.6–1.3 秒/请求，避免给 B 站造成负担）
#    原始数据只进 data/raw-local/
python3 bili/collect.py --pages 3 --comment-pages 1

# ② 匿名化：拆成「本机留档」+「可发布」
python3 analysis/anonymize.py

# ③ 分析（自动优先读 raw-local 的原始评论；没有则用发布版派生指标）
python3 analysis/analyze.py

# ④ 画图（与 analyze 共用同一套分位数算法，结尾自动交叉核对）
python3 analysis/make_figures.py
```

产出：

```
data/raw-local/        原始数据 + id 对照表 + 请求日志      （不进 git）
data/videos.jsonl      匿名后的视频 stat（owner_ref: u01…）
data/comments.jsonl    每视频一行的派生指标（唯一文本数/重复率/长度/等级）
data/analysis.json     逐视频的指标与有符号偏离度（键 v01…）
report/数据观察.md      可读报告
report/figures/*.svg   2 张图（零依赖手写 SVG）
```

### 一键验证（数字可追溯）

```bash
python3 analysis/verify.py     # 29 项自检：重跑管道 + 数字自洽 + 隐私无泄漏
```

跑完会打印本报告里用到的每个数字：n、唯一评论数、各互动比的中位数与极差、
触发标记的视频、以及每个标记在本批数据里**是否可达**。报告表里的中位数与
图2 里的中位数由同一个 `percentile()` 算出，`make_figures.py` 结尾会断言二者一致。

`verify.py` 还会检查：发布版数据里搜不到真标题/UP 名/评论文本/uid_hash、
`analysis.json` 只剩稳定 id、报告里不再出现旧的错误说法（如「10–100 倍」「本样本里就有 14% 的」）。
**任何一项失败都会返回码 1。**

## 已知局限（照实写）

| 局限 | 说明 |
|---|---|
| **n = 18** | 45 个视频里 27 个一条评论都没取到。旧版采集器的接口返回码被丢掉，**当时为什么返回 0 条已不可考**（现在有 fetch_log 可查）。所有评论类指标的 n 都是 18 |
| **样本来自热门榜** | 刷量视频通常上不了热榜 → 本批样本本来就抓不到注水 |
| **评论只有第 1 页** | `pn` 参数无效，每视频最多 20 条唯一评论 → 比例类指标的置信区间很宽 |
| **`q3_rate` 恒为 0** | 353 条唯一评论里没有任何一条含 3 个以上连续问号 → 该指标在本批数据里**没有信息量**，图3 已删除 |
| **弹幕数据缺失** | 弹幕接口需登录 + 签名。弹幕本应是「问号」的最佳数据源（比评论短促、密度高） |
| **文本重复度无法区分性质** | 「跟风刷梗」与「水军灌入」在文本特征上相同 |
| **单一时间点** | 没有时间序列 → 无法做"增长曲线突变"检测 |
| **不做判定** | 全篇只报告指标与偏离度，**不对任何视频或账号做定性** |

## 立场与边界

```
· 只用公开接口，不登录、不抓取需要授权的数据
· 不做任何刷量操作，也不提供获取虚假互动的方法
· 不点名指控任何账号或 UP 主 —— 只报告指标分布；发布版不含真标题与 UP 名
· 不保存原始身份：发布版不含 uid，也不含可反查的用户哈希
· 不接受单账号委托，不出具单视频报告
· 限速请求，不给平台造成负担
· 欢迎指出方法错误 —— 尤其是"偏离"与"注水"之间被我混淆的地方
```
